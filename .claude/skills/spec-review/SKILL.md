# Spec Review Skill

## Overview

設計書と実装コードを照合し、仕様との差分を検出する。
「コードの品質」ではなく「仕様との適合」を確認することが目的。

---

## Procedure

1. `docs/[機能名]/plan.md` を読み込む（存在する場合）。feature-modify から実行された場合は、差分設計の「クラス仕様（契約）の変更」も照合の材料とする
2. 実装済みのコードを読み込む（変更されたファイルを対象とする）
3. 設計書から要件項目を抽出する
4. 要件項目ごとに実装の有無・内容を照合する
5. plan.md または差分設計にクラス仕様（契約）が記載されている場合、契約の各項目（不変条件・事前条件・事後条件）について以下を照合する
   - 実装に反映されているか（コンストラクタでの検証・JSDoc の `@throws` / `@returns` 等）
   - 対応するテストが実装と同じ単位フォルダにあるか（テスト名とアサーションが、その契約項目を検証しているかで判定する）
   - テストがない契約項目（未カバー）は「未実装」にも記載する
6. 以下の形式で報告する

---

## Output Format

違反がある場合：

```
## 仕様突き合わせ結果

### 実装済み（仕様通り）
- [要件項目]: [該当ファイル:行番号]

### 未実装
- [要件項目]: 実装が確認できない

### 仕様と異なる実装
- [要件項目]
  - 仕様: ...
  - 実装: [ファイル:行番号] ...
  - 差分の概要: ...

### 契約とテストの対応
（plan.md または差分設計にクラス仕様（契約）が記載されている場合のみ）
| クラス・メソッド | 契約項目 | 実装 | テスト | 判定 |
|---|---|---|---|---|
| TaskTitle.constructor | 事前条件: 空でない | task-title.ts:15 | task-title.test.ts「空文字でエラーになること」 | ✓ |
| TaskTitle.constructor | 事前条件: 100 文字以内 | task-title.ts:19 | なし | 未カバー |
```

違反がない場合：

```
## 仕様突き合わせ結果

チェック完了。仕様通りに実装されています。

### 契約とテストの対応
（plan.md または差分設計にクラス仕様（契約）が記載されている場合のみ。全項目が ✓ であること）
| クラス・メソッド | 契約項目 | 実装 | テスト | 判定 |
|---|---|---|---|---|
```

---

## Constraints

- コードの品質・パターンは対象外（それは backend-review / frontend-review が担う）
- 設計書（plan.md）も、feature-modify の差分設計の「クラス仕様（契約）の変更」もない場合は実行しない
- 「仕様と異なる」の判定は明確な差分があるときのみ行う（曖昧な場合はユーザーに確認する）
- テストの有無は、ファイルの存在ではなく、テスト名・アサーションがその契約項目を検証しているかで判定する
