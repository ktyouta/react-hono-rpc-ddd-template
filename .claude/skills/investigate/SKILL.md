# Investigate Skill

## Overview

調査・確認・原因究明を依頼されたとき、関連ファイルを網羅的に読み込んでから回答する。

「起点ファイルだけ読んで回答する」という局所的な調査を防ぐことが目的。
Phase 1 で起点を特定し、Phase 2 でファイルをたどり切ってから回答する。

---

## Steps

### Phase 1: 起点探索

調査対象に関連する起点ファイルを特定する。

1. ユーザーの発話から調査対象（ファイル名・機能名・クラス名・エンドポイント・エラー文言）を確認する
2. Glob で対象フォルダのディレクトリ構造を確認する
3. Grep で関連シンボル・キーワードの出現ファイルを特定する
4. 起点ファイルのリストを作成する（この時点ではまだ Read しない）

---

### Phase 2: 関連ファイル展開

起点ファイルから関連ファイルをたどり、全件読む。

1. 起点ファイルを全件 Read する
2. 読んだファイルの **import 文・参照先・型定義ファイル** を確認する
3. 新たに見つかった関連ファイルを Read する
4. 新たなファイルが見つからなくなるまで 2〜3 を繰り返す

> **スキップ条件**: import 先が `node_modules` 配下の場合はスキップしてよい。
> ただし、回答の結論がライブラリの挙動（例外の発生条件とメッセージ・型定義・入力の解釈など）に依存する場合はスキップしない。
> 該当ライブラリの実装（`dist/**/*.js`）と型定義（`*.d.ts`）を Read し、読み込んだファイルの一覧に含める。読まずに述べる場合は「未検証」と明記する

---

### Phase 3: 回答

全ての関連ファイルを読んだ状態で回答する。

問題の有無・重大さは、CLAUDE.md と設計書（`docs/**/plan.md`）の方針に照らして判定する。
発生頻度（「通常の操作では起きない」など）を理由に、方針違反を問題なしと扱わない。

回答の冒頭に読み込んだファイルの一覧を記載する：

```
## 読み込んだファイル
- path/to/file-a.ts
- path/to/file-b.ts
...
```

---

## Constraints

- Phase 2 を省略しない。「起点ファイルだけ読んで回答した」状態はこのスキルの違反
- 「ファイルが多すぎる」という理由で Phase 2 をスキップしない
- 回答冒頭の「読み込んだファイル一覧」を省略しない
- 関連ファイルを全件読み終える前に回答を開始しない
- ユーザーが「別の環境で失敗した」「不安定」と示唆した事象は、1回の成功で否定しない。複数回（3回以上）実行して再現しないことを確認してから結論を出し、回数を回答に記載する
- 結論がライブラリの挙動に依存する場合、ライブラリの実装・型定義を読まずに推測で断定しない（読まない場合は「未検証」と明記する）
- 発生頻度の低さを理由に、CLAUDE.md・設計書の方針に反する挙動を問題なしと扱わない
